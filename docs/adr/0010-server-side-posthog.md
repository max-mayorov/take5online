# Server-side PostHog: Worker events, errors, logs and kill-switch flags

We wanted more of PostHog's free products without giving up [ADR-0009](./0009-posthog-analytics.md)'s cookieless, banner-free setup. In cookieless mode, posthog-js can't record session replays, doesn't show surveys, and gives every visitor the same id, so experiments can't split traffic; those stay off. Heatmaps, dead clicks and Core Web Vitals need no storage, so the browser now sends them. The Worker and each Room report their own exceptions, OpenTelemetry logs and Room events (created, Game started and ended, expired) straight to PostHog's API with a few lines of `fetch` instead of an SDK. They are about Rooms, not people: they carry the Room Code and counts but no IP, Nickname or Member id, and they turn off GeoIP and person profiles, so they still count Games when a browser blocks analytics. Feature flags are kill switches, not per-person rollouts: the Worker evaluates them once for everyone, caches them for a minute and serves them at `/api/flags`, so a switch works for visitors who opted out too and the request says nothing about them. Only production sends or asks anything (CI deploys with `--var POSTHOG:on`), so dev servers, tests and PR previews stay quiet. CI uploads the web app's source maps to PostHog and `.assetsignore` keeps them off the site. The costs: no replay, surveys or experiments; a flag change takes up to a minute to arrive; Worker stack traces show bundled line numbers, because only the web app's maps are uploaded.
